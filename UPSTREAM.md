Local packaging adaptations:

- Public APIs are split into root, blocks, markdown, icons, theme, and theme/bootstrap entries.
- `.ts`/`.tsx` source specifiers are rewritten in emitted declarations.
- CSS Modules are compiled to idempotent style injection code.
- KaTeX CSS is not imported by Markdown; the package publishes explicit woff2-only CSS and font assets. Re-applied on every sync: upstream `markdown/MarkdownText.tsx` imports `katex/dist/katex.min.css`.
- Theme persistence and bootstrap are standalone and do not use DSH settings or Cordis services.
- KaTeX's trusted generated markup uses an SSR-safe React wrapper instead of the upstream browser-only `DOMParser` conversion.
- `HoverCard` fixes the alpha.3 dark-surface foreground omission by explicitly using white text in both themes.
- The file/link icon family (`FileTypeIcon`, `classifyFileType`, `fileExtension`, `LinkIcon`, `classifyLinkPath` and their types) is exported from the `blocks` entry instead of the root: `FileTypeIcon` embeds ~57KB of code-file artwork (`code-file-icon-artwork.ts`) and `assertLightweightRoot` forbids the root from reaching it. `WebBlock` and the Markdown renderer already import it, so the blocks and markdown entries gain no weight.
- `MessageText` was removed upstream in rc.2 (`d0da8ccf40`); the `markdown` entry drops it too — a breaking change for 0.2.0 consumers of the standalone package.
- `code-file-icon-artwork.manifest.json` is copied as the upstream design record; no source imports it.
- `Tooltip` creates its suppression context only where React provides `createContext` (0.1.7): the `react-server` build has none, and a Server Component evaluates `Tooltip.tsx` through the root entry because the server-safe `Empty` imports `Button` from it. Upstream's module-level `createContext` call failed the `next16` fixture with `createContext is not a function`. Tooltip only renders on the client, so behaviour is unchanged. Since rc.2 upstream exports `TooltipSuppression` (HoverCard consumes it); the export is kept, still behind the guard. `TextShimmer`'s `DecorativeCopy` context (0.2.0) is created behind the same guard for the same reason: `DisclosureRow` pulls it into the root entry.
- Upstream exports `CodeToolbarLabels`, `CODE_HIGHLIGHT_EXTENSIONS`, `languageForPath`, `useCodeHighlighter` (and their types) from its root; they live in `blocks` here because they reach the Shiki highlighter, which `assertLightweightRoot` keeps off the root. `MarkdownDelegateProvider` and its types go to `markdown`; `PermissionIcon*`, `ReferenceIcon*`, `PluginArtwork*` and (rc.2) `GuideArtwork*` go to `icons`; `LinkIcon*` stays in `blocks` with the rest of the file/link family. `MenuSurface`, `ShortcutKeys`, `useModalLayer` and the focus / composition helpers stay on the root as upstream has them.
- Not mirrored: `PathLabel.*` and `settings-form/` (`SettingsForm`, `SettingsSecretField`, `SettingsValueField`, `SettingsFormModel`, `settingsNumberField`, `settingsTextField` and their types). They import `@deepseek-ai/dsh-util-workspace-path` and `@deepseek-ai/dsh-client-store` (zustand + immer, Cordis peer), which this Cordis-free standalone package does not take on; nothing here consumes them. Revisit when a consumer appears.
- Not mirrored: `ui-theme`'s opt-in `brand-font.css` with its three Montserrat woff2 files and OFL text. It is not one of the six theme sheets (upstream's `installThemeStyles` does not load it either); only the desktop welcome page uses it.
- Not mirrored: `BrandWordmark.tsx` and `FishLogo.tsx` (with `FISH_LOGO_PATH` / `FISH_LOGO_VIEWBOX`). They draw DeepSeek's wordmark and logo; MIT licenses the code, not the trademarks, so this public package ships no DeepSeek brand assets. Drop both files again on every sync.
- `simple-icons` (pinned `16.31.0`, same as upstream) is a runtime dependency: `LinkIcon*` draws known sites' marks through `SiteGlyph.tsx`.
- Type / lint-only edits, re-applied on every sync: `useRef<T | undefined>(undefined)` in `JsonTree.tsx` and `RefObject<… | null>` in `useAnchoredMaxHeight.ts` / `markdown/useViewportHighlighting.ts` (React 19 `@types/react`); `catch {}` without the unused binding in `markdown/file-link.ts` (root oxlint `no-unused-vars` is an error).

## SeekBuddy extension layer (not synchronized)

`src/seekbuddy/` and the `@seekbuddy/dsh-ui/seekbuddy` entry family are SeekBuddy-owned and have no
upstream counterpart. Synchronization must leave that directory untouched, and nothing under it
may be copied back into the mirror. The build asserts every extension entry bundles only `src/seekbuddy/*`
(upstream primitives are consumed through the public `@seekbuddy/dsh-ui` entry, kept external).

`storybook/` is also SeekBuddy-owned and not synchronized: a self-contained Storybook island (own
`package.json` / `node_modules`, not a workspace member) that documents both layers by reading
`src/` directly. It never enters `dist/`, the npm `files` list, or any plugin bundle. Stories may
describe mirror-layer components (`parameters.docs.description`) but must not edit their source.

## Repository origin

This repository is the source of truth for `@seekbuddy/dsh-ui`. It was created from the SeekBuddy monorepo's `packages/ui` (package `dsh-ui-primitives`) at commit `5db817380bfdb2ace334e814c1ed7f345feb4225`; that copy had itself been imported from `https://github.com/seekbuddy/dsh-ui-primitives` at `db5f935301b73acd7062256e48d05312f02e52c6`. Runtime identifiers keep the old name for compatibility with that copy: the style-injection attribute `data-dsh-ui-primitives` and the theme storage key `dsh-ui-primitives.theme-preference`.

- `tokens.css` is built from eight sheets since rc.2: `base`, `corner-shape`, `design-platform`, `focus`, `onboarding`, `scrollbar`, `gradient-shadow-text`, `shiki`, in upstream's `ui-theme/src/client/styles.ts` order. `input-modality.ts` publishes `data-input-modality` on `<html>` from module-level listeners; it is reached through `Tooltip`, so the root entry installs it in an app exactly as the host does.
